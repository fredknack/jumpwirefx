# jumpwirefx Phase 2: CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Fred add and edit projects, upload their media, and publish from `/admin`, with content stored in Postgres and the public site reading it through the existing content module.

**Architecture:** Neon Postgres through Drizzle ORM. `lib/content.ts` becomes a switch: with `DATABASE_URL` set it reads the database inside `"use cache"` functions tagged `content`; otherwise it reads the Phase 1 seed files, so the site builds and tests run without a database. Admin pages are server components with server actions; a single admin password (bcrypt hash in env) exchanges for a signed JWT cookie that `proxy.ts` checks on `/admin/*`. Uploads go browser-to-Blob through a token route that requires that cookie. Saves call `revalidateTag("content")`.

**Tech Stack:** `drizzle-orm`, `drizzle-kit`, `@neondatabase/serverless`, `@electric-sql/pglite` (tests only), `zod`, `jose`, `bcryptjs`, `@vercel/blob` (client upload), existing Next.js 16 / Vitest setup.

**Spec:** `docs/superpowers/specs/2026-10-28-jumpwirefx-site-design.md` (section "Phase 2 — CMS")

## Global Constraints

- Everything in the Phase 1 plan's Global Constraints still holds.
- Pages never import the database directly; only `lib/content.ts` and `lib/db/*` do.
- Without `DATABASE_URL`, `pnpm build` and `pnpm test` succeed using the seed files.
- Session cookie: name `jw_admin`, HttpOnly, Secure (except on localhost), SameSite=Lax, path `/`, 7-day expiry, JWT HS256 signed with `AUTH_SECRET` (32+ bytes).
- Env vars, all documented in `.env.example`: `DATABASE_URL`, `AUTH_SECRET`, `ADMIN_PASSWORD_HASH`, `BLOB_READ_WRITE_TOKEN`.
- Failed logins: after 5 failures from one IP within 15 minutes, respond "Too many attempts" for 15 minutes (in-memory map; acceptable for one admin).
- Delete requires a typed confirmation of the project slug.
- Slugs: lowercase `a-z0-9-`, unique, 3-80 chars; derived from the title on create, editable afterwards.

## Review Focus

1. Saving a project with a slug that already exists must show a field error, not a 500. Test in Task 3.
2. A request to `/admin/projects` with no cookie, an expired cookie, or a cookie signed with another secret must redirect to `/admin/login`. Test in Task 4.
3. An upload token request without a valid session must return 401 and never mint a Blob token. Test in Task 6.
4. Unpublishing a project must remove it from the home grid and sitemap on the next request (revalidation), and its URL must 404. Test in Task 5.
5. With `DATABASE_URL` unset, every public page and `pnpm build` still work from seed files. Test in Task 2.
